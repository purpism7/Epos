# 화면 자체검수 — 넘기기 전에 스스로 본다

> 지위: ⚑ 첫 판(2026-11-25 · 팀장이 씀) · 효과는 «AI 개발 수업» 1강 시험 A로 잰다(`Docs/60_AI개발/AI-개발-수업-한장.md`).
> 출처: 널리 쓰이는 공개 스킬 둘에서 **원리만** 옮겨 우리 말로 고쳐 씀 — «증거 먼저, 말은 나중»(완료 전 검증) · «먼저 화면을 보고, 그다음 누른다»(웹 화면 시험). 원본에 딸린 실행 파일은 가져오지 않았다.
> 왜: 핸드폰에서 깨진 판이 팀장 · 제제에게 넘어온 일이 있었다(할 일 2-6). 🔵 제제 2026-11-25 — «불필요한 검수 과정을 줄이기 위해 화면을 확인하는 등의 자체 검토 과정을 둔다».

## 철칙
**이번 차례에 새로 얻은 증거 없이 «됐다»고 말하지 않는다.** 앞서 돌린 시험 · 다른 세션의 «성공» · «그럴 것이다»는 증거가 아니다.

## 걸음 다섯 (하나라도 건너뛰면 검수가 아니다)
1. **증거를 먼저 정한다** — 고친 것마다 «무엇을 보면 됐다고 말할 수 있나»를 한 줄로 적는다.
   예: «결과 창의 낯선 소수를 없앰» → 결과 창 캡처에 `0.07` 같은 글이 없다.
2. **시험을 새로 돌린다** — `npm run check` 전체. 숫자를 그대로 옮긴다(통과 몇 · 실패 몇). 시뮬을 건드리지 않은 일이면 골든이 그대로인지도 본다(바뀜 0).
3. **화면을 찍는다** — 핸드폰 가로 크기 셋 이상(⚑ 640×260 · 844×390 · 915×412). 있는 도구를 먼저 쓴다: `npm run check:phone`(넘침 · 겹침 숫자) · `npm run shots:phone`(캡처) · 점 그림 판은 `npm run pixel:shots`. 도구가 고친 화면까지 닿지 않으면 앱 안 브라우저로 직접 열어 찍는다.
4. **캡처를 열어서 본다** — 파일이 생겼다는 것은 증거가 아니다. 그림을 직접 열고 다섯 가지를 본다.
   ① 고친 것이 보이나 ② 겹침 · 잘림이 없나 ③ 사람이 볼 화면에 개발용 글 · 낯선 글(소수 · 영어 · 변수 이름)이 없나 ④ «지금 뭘 누르나»가 읽히나 ⑤ 다른 곳이 깨지지 않았나(고치기 전 캡처와 나란히)
5. **그다음에만 말한다** — 보고의 «확인한 것»에 증거(숫자 · 캡처 파일 이름 · 크기)를 붙이고, 못 본 것은 «확인 못 한 것»에 적는다.

## 이 말이 나오려 하면 멈춘다
«아마» · «될 것이다» · «보기엔 괜찮다» · 시험 전에 «됐습니다!» · 다른 세션이나 도구가 «성공»이라 한 것을 그대로 옮기기 · «이번만 건너뛰자»

| 핑계 | 실제 |
|---|---|
| 코드를 고쳤으니 고쳐졌다 | 처음 증상을 다시 재 봐야 안다 |
| 시험이 다 통과했다 | 시험은 화면을 보지 않는다 — 캡처를 본다 |
| 캡처 파일이 생겼다 | 열어 보지 않으면 증거가 아니다 |
| 한 크기에서 괜찮다 | 낮은 가로 화면에서 깨진다 — 셋 이상 |
| 다시 찍기엔 시간이 아깝다 | 되돌아오면 두 배가 든다 |

## 하지 않는 것
- 증거를 만들려고 시뮬 규칙을 고치지 않는다(결정론 · 표현 분리 — `CLAUDE.md` 2절).
- 팀장 검수를 대신하지 않는다 — 이 스킬은 **팀장 검수 앞의 거름**이다. 팀장은 여전히 직접 본다(`CLAUDE.md` 4절 3).
- 커밋 · 보고의 규칙은 맡은 곳의 규칙 그대로다(보고 7줄 · 금지선).
