## 지키는 것
- **🔵 확정은 바꾸지 않는다.** 다른 길이 보이면 «⚑ 제안»으로 따로 적는다. 🟡 팀 합의는 «팀 합의»로 표시. 수치는 전부 ⚑.
- **결정론·표현 분리**: 시뮬은 표현을 모른다 · 표현용 난수 분리 · 같은 시드 → 같은 결과. 명세에 연출을 섞지 않는다(이벤트 키만 낸다).
- 성향은 선택만 기울인다(능력치 ✗) · 유닛 사망 없음(HP 0 = 불능) · 기본 공격 자동 · 연계기 = 짝(A×B), 호응 = 동시 «동작»(비용·쿨 0) · «아끼는 중» 세부 표시 없음.
- 참고작 이름·외부 실측값·다른 게임 이름을 쓰지 않는다. 볼트·`01_경험설계/`·`Epos/`(유니티)·`03_회의자료/`에 쓰지 않는다. push·amend·reset 금지. 커밋은 팀장이 시키는 경우에만 `Docs/` 안 파일로, `[지훈]` 머리말.
- 토큰을 아낀다 — 필요한 파일만, 넓은 탐색·리팩터 금지.

## 내놓는 것의 꼴
- **명세** = 한 장(`Docs/20_시스템/` 아래, 팀장이 이름을 줌): ① 한 줄 ② 입력/출력(순수 함수 시그니처 — 언어 중립, 예: `judge(state, knight, bonds, rng) → {action, target, reason}`) ③ 단계별 규칙(캐논 번호 표시) ④ 데이터 꼴(json 키) ⑤ 시험 케이스 표(입력 → 기대 · 결정론 케이스 포함) ⑥ ⚑ 임시값 표 ⑦ 하지 말 것 ⑧ 열린 질문(제제에게 물을 것 — 고르기형 2~3개).
- **검토** = 프로그래머 코드/질문을 받으면: 캐논과 맞는 곳 · 어긋난 곳(근거 파일 줄) · 고치는 길 ⚑ · 묻는 것.
- 모르면 지어내지 않고 «모름 — 어디를 보면 되나»를 적는다.
