## ① 한 줄
연계기는 스킬 칸이 아니라 **두 기사의 관계(짝 A×B)에 1건**이고, 호응은 A가 궁극기를 **쓰는 순간** 근처의 B가 **동시에 하는 동작**이다 — B의 궁극기가 아니며 비용·쿨타임 0 🔵 [스킬 §2 · §3 · 원리 §1]. 판정은 난수를 쓰지 않고(⚑), 호응이 만든 타격만 5단계에서 판단 명세의 난수 규칙대로 굴린다(⚑).

## ② 입력 / 출력 (순수 함수 시그니처 — 언어 중립 · 이름은 전부 ⚑)
| # | 함수(뜻) | 입력 | 출력 | 난수 |
|---|---|---|---|---|
| C1 | `comboResponders`(누가 호응하나) | `fire, state, rules` | `picks[]` — `{ knightId, bondId, special, action, dist, order }` · order 0부터 | 0번 |
| C2 | `comboApply`(호응 결과) | `fire, picks, state, rules` | `{ fireDef, strikes[], events[] }` — `fireDef` = A 궁극기 값(넓히기면 범위만 바뀜) · `strikes` = 따라 찍기 타격(주체 = B) · `events` = `combo` 키 | 0번 |
| 도움 | `bondOf(rules, a, b)` · `ultKindOf(rules, ultDef)` · `responseOf(bond, casterKey, kind)` | | 관계 1건 또는 없음 · `strike`/`protect` · `{ special, action }` | 0번 |

- 🔵 호응 판정은 **순수 함수**(입력: 발동 기사 · 짝 목록 · 위치 · 상태 → 출력: 호응자 목록 + 종류) · 같은 시드 → 같은 결과 · 연출은 이벤트를 받아서만 그린다 [스킬 §4 · 원리 §1 · §7].
- ⚑ `fire` = 이번 틱에 **발동한** 궁극기 1건 `{ casterId, ultId, aim: [x, z], tick }` — 전투 처리부가 낸다(언제 발동하는지는 판단 명세처럼 이 장 밖). 판단 명세의 부작용 없음 조건 1~6을 C1 · C2도 그대로 지킨다 [판단 ②].

**묶는 함수 한 틱 안의 자리** ⚑ — 판단 명세 ㉱를 이렇게 나눈다 [판단 ② ㉮~㉱]
- ㉱-1 전투 처리부가 이번 틱의 착탄 `strikes`(4단계 «즉시» 스킬 + 자동 기본 공격)와 발동 `fires[]`를 낸다.
- ㉱-2 `fires`를 **시전자 id 오름차순**으로 하나씩: C1 → C2. C1 · C2는 **틱 시작 때의 `state`만** 읽는다(1~4단계와 같음 — 같은 틱 A의 타격으로 바뀐 자리·체력을 보지 않는다) [판단 ㉯ · `combo.ts:74`].
- ㉱-3 넓히기면 그 A의 궁극기 착탄을 `fireDef`로 갈아 끼우고(표적 다시 모음) · 따라 찍기 `strikes`를 목록에 더한다.
- ㉱-4 5단계 `resolve` → 6단계 `feedback` → `nextState`. 이벤트는 틱 끝에 한꺼번에 [판단 ② 조건 5].
- 판단 1~4단계는 바뀌지 않는다 — 호응은 B의 판단(후보·점수·보류)을 거치지 않는 **동작**이다 🔵 [스킬 §3 «B의 궁극기가 아니다»].

## ③ 규칙
### 1. 순간 · 누구
- 1-1 🔵 순간 = A가 궁극기를 **쓰는 순간(발동 틱)** [스킬 §3]. ⚑ 발동 틱 = 예고(준비 동작)가 끝나 실제로 터지는 틱 — 내려찍기는 착탄 틱 · 관통 돌진은 출발 틱 [`combo.ts:8` · `enemyUlt.ts:113-114`]. 예고 중에는 판정하지 않는다.
- 1-2 🔵 적은 호응하지 않는다(현 단계) [원리 §1 · 스킬 §3] → ⚑ A가 상대 팀(team 1)이면 `picks` = 빈 목록. 스위치 `rules.combo.enemy` = false [`combo.ts:47` · `arenaBonds.json:15`].
- 1-3 🔵 B = **관계 있는** 같은 편 · 자기 아님 · **살아 있고 그로기 아님** [스킬 §3]. 🔵 HP 0 = 전투 불능(사망 없음) [원리 §1] → 불능은 빠진다 [`combo.ts:50`].
- 1-4 ⚑ 그 밖의 상태(물러서는 중 · 공중 · 경직 · 자기 궁극기 예고·돌진 중)는 **막지 않는다** — v0와 같음 [`combo.ts:50` — 생존·그로기만 본다] → ⑧ 질문 2.
- 1-5 🔵 관계(인연)는 지금 **켜짐/꺼짐뿐** — 꺼진 짝은 근처여도 호응하지 않는다 [스킬 §2 · §3 v0 시연 짝 · `combo.ts:51`].
- 1-6 🔵 근처 = ⚑ 3칸(특화 짝은 짝마다 따로 — 검×메이지 4칸) · 근처에 없으면 일어나지 않는다 [스킬 §3 · 원리 §1]. ⚑ 거리 = 틱 시작 때 **A 자리**와 B 자리의 중심 거리 · `거리 ≤ near`면 근처(같으면 들어감) · 짝에 `near`가 있으면 그 값, 없으면 `rules.combo.near` [`combo.ts:52`].

### 2. 무엇을 하나
- 2-1 🔵 종류: 타격형 궁극기 → **따라 찍기**(⚑ 0.5배 · 같은 조준점) · 보호형/특화 → **넓히기**(⚑ 범위 1.5배 · 피해 그대로) [스킬 §3 · 원리 §1].
- 2-2 🔵 방향: 특화는 한 방향으로 정의(검 궁극기 → 메이지 호응) · 반대 방향은 범용 규칙 [스킬 §3]. ⚑ 식: `special.from` = A면 `{ special: special.id, action: special.action }` · 아니면 `{ special: '', action: 궁극기 분류가 protect면 widen, 아니면 follow }` [`combo.ts:36-41`].
- 2-3 ⚑ 궁극기 분류 = `rules.combo.ultKinds[ultId]` · 없으면 효과로(보호막·회복 = 보호형, 그 밖 = 타격형) [`combo.ts:31-34` · `arenaBonds.json:17`].
- 2-4 ⚑ 따라 찍기 = B를 주체로 하는 범위 타격 1건: 중심 = A의 조준점 · 반경 = A 궁극기 반경(관통 돌진이면 종점 반경 `endRadius`) · 피해 · 체간 · 밀침 = A 궁극기 값 × `followMul` [`combo.ts:64-68`]. **넓히기가 같이 있어도 따라 찍기 반경은 원래 반경** [`combo.ts:97`].
- 2-5 ⚑ 넓히기 = B의 타격은 없다 — A 궁극기의 반경만 × `widenMul`, 나머지(피해 · 보호막 양)는 그대로 · 넓히기 호응이 여럿이어도 **한 번만** 곱한다(1.5², 2.25 아님) [`combo.ts:60-63 · 69-70 · 9`].
- 2-6 🔵 비용 · 쿨타임 **0** — B의 마나 · 액티브 쿨 · 궁극기 쿨·준비 시간 · 자리 · 표적 · 다음 판단 시각을 **하나도 바꾸지 않는다** [스킬 §3 · §5 · `combo.ts:9 · 94`]. ⚑ C2의 `patch`에 B의 키는 없다.
- 2-7 ⚑ 표적 모으기(따라 찍기 · 넓힌 궁극기 둘 다) = 틱 시작 때 HP > 0인 상대 팀 기사 중 중심 거리 ≤ 반경 · **id 오름차순**. 같은 틱의 타격은 «동시» — A의 궁극기에 쓰러진 적도 따라 찍기 판정을 받는다 [판단 5-4]. (v0와 다름 → 아래 «어긋난 곳» 6.)

### 3. 순서 · 상한 (컷인이 쌓이는 순서 = `order`)
- 3-1 🔵 호응 기사는 **참여 순서대로** 컷인이 쌓인다 [스킬 §3 · 원리 §3]. ⚑ 참여 순서 = ① 특화 짝 먼저 → ② 거리 가까운 순 → ③ id 오름차순 [`combo.ts:55`]. 거리는 제곱으로 견줘도 같은 순서 — 동점은 반드시 ③까지 간다. **입력 목록의 순서에 기대지 않는다.**
- 3-2 ⚑ 상한 `maxResponders` 2 — 순서대로 자른다 [`combo.ts:56-57` · `arenaBonds.json:16`]. 정본에는 상한이 없다 → ⑧ 질문 1.
- 3-3 ⚑ 같은 틱에 궁극기가 여럿 발동하면 시전자 id 오름차순으로 따로 판정한다 — 한 B가 두 A에 각각 호응할 수 있다(비용 0이므로 막을 까닭 없음).

### 4. 난수 자리(못 박음) ⚑ — 판단 명세 난수 규칙과 어긋나지 않게 [판단 «난수 규칙» 1~5 · 원리 §1]
1. C1 · C2는 난수 **0번**. 난수는 여전히 **5단계 하나**에서만.
2. 따라 찍기 1건 = 주체 B의 타격 → **(B × 표적) 1쌍마다 정확히 2번**(① 성패 ② 품질) — 판단 명세 규칙 2 그대로.
3. 넓히기 = 따로 굴리지 않는다. 넓어져 늘어난 (A × 표적) 쌍만큼 A의 궁극기 굴림이 늘어난다(1쌍마다 2번).
4. 순서: 판단 명세 규칙 3의 «공격자 id 오름차순 → 한 공격자 안에서 궁극기 · 액티브 · 기본 공격 → 표적 id 오름차순»에 **«호응» 칸을 궁극기 바로 뒤에 끼운다** — 한 공격자 안: 궁극기 → 호응(여럿이면 시전자 A id 오름차순) → 액티브 → 기본 공격. (판단 명세 난수 규칙 3에도 같은 날 반영함.)
5. 호응 스위치를 끄면(`rules.combo.enabled` = false) C1은 빈 목록 → 굴림 수 · 상태 해시 = 옛 판 그대로 🔵 새 규칙은 스위치로 [스킬 §4 · `combo.ts:46`].

### 5. 표현으로 나가는 것 = 이벤트 키만 ⚑ (꼴 `{ key, tick, 주체, 대상, 좌표 }` — 뜻만 [판단 «이벤트 키»])
- `combo` = `{ key, tick, src: A, dst: B, pos: 조준점, kind: follow|widen, special, order, radius, extra }` — 호응 1건마다 · `order` 순서로 목록에 넣는다 · `extra` = 넓혀서 더 맞은 수(첫 넓히기에만, 그 밖 0) [`types.ts:156` · `combo.ts:102 · 107`].
- 따라 찍기의 적중은 5단계의 `hit`(주체 B · `kind: combo`)로 나간다. **내지 않는 것**: B의 `ultCast` · `activeCast` · 쿨·마나 변화 키 · 연출 값(말풍선 문구 · 금색 끈 · 배너 · 컷인 위치).
- 결과 창 «연계 n회» = 그 판 `combo` 이벤트 수 🔵 [스킬 §3 «결과 창»] (세는 것은 화면 몫).

- 🔵 궁극기+궁극기를 동시에 맞추라고 요구하지 않는다 · 모든 짝에 특화를 주지 않는다 [스킬 §5].
- 🔵 적 팀 호응을 켜지 않는다(현 단계) · 근처가 아니거나 관계가 꺼졌으면 일어나지 않는다 [스킬 §3 · 원리 §1].
- 🔵 표현을 위해 판정을 고치지 않는다 · 이벤트에 연출 값을 담지 않는다 · 시뮬 난수와 표현 난수를 섞지 않는다 [원리 §1 · §7].

## ⑧ 열린 질문 (제제에게 — 고르기형)
1. **궁극기 한 번에 몇 명까지 따라오나?** (v0는 2명까지 · 정본엔 상한이 없다 · 기사 4명이면 최대 3명이 따라올 수 있다.)
   - **가(권장)** 2명까지(v0대로). — 얻는 것: 컷인이 2장까지만 쌓여 1초 안에 읽힌다 / 잃는 것: 4명 편성에서 한 명은 근처여도 안 따라온다(왜 안 왔는지 헷갈릴 수 있다).
   - **나** 근처의 관계 있는 기사는 전원. — 얻는 것: «다 같이 터뜨린다»는 큰 장면 / 잃는 것: 컷인 3장 · 피해가 크게 늘어 밸런스를 다시 맞춰야 한다.
2. **물러서는 중이거나 자기 궁극기를 준비 중인 기사도 호응하나?** (정본은 «살아 있고 그로기 아님»만 적었다.)
   - **가(권장)** 한다 — 불능·그로기만 뺀다(v0대로). — 얻는 것: 호응이 자주 보이고, 규칙이 단순하다 / 잃는 것: 도망치던 기사가 갑자기 따라 찍는 장면이 어색할 수 있다(뛰어드는 움직임은 아직 미정).
   - **나** 스스로 스킬을 쓸 수 없는 상태(물러섬 · 공중 · 경직 · 준비 중)면 안 한다. — 얻는 것: 행동이 앞뒤가 맞아 보인다 / 잃는 것: 호응이 덜 보이고, 판단 명세 2-8 목록과 묶여 규칙이 길어진다.
