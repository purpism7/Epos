# 다른 AI 쓰는 법 한 장 — 지피티는 그림, 제미나이는 영상

> 지위: **🔵 원리**(제제 2026-11-25 — 1절) · 모델 이름 · 노력 · 점검 항목 · 길은 **⚑**(팀장이 시험하며 고친다) · 마지막 확정 2026-11-25 · 새 장. 볼트 `3_AI`의 6월 기록(다자회의 역할 분담 · 마스터 워크플로 · 고도 협업 회고)은 이력이다 — 그때 배운 «같은 파일을 둘이 동시에 고치지 않는다» · «AI가 화면을 못 보는 것이 가장 큰 막힘»은 이 장의 뿌리.

## 1. 정한 것 (🔵 제제 2026-11-25)
1. **머리는 하나** — 정본(`Docs/`) · 판정 · 커밋은 클로드 팀장. 다른 AI는 **재료와 두 번째 눈까지**.
2. **특기만 맡긴다** — 지피티 = 그림 만들기 · 제미나이 = 영상 분석. 범용 역할은 주지 않는다(구독이 가장 싼 것이라 사용량이 적다). 제미나이에게는 그림을 맡기지 않는다.
3. **일감 크기에 맞는 모델** — 작은 일 · 가벼운 일에 큰 모델을 쓰지 않는다. 크고 판단이 중요한 일에만 큰 모델.
4. **넘기기 전 자체 검토** — 불필요한 검수를 줄이려고, 결과를 받은 세션이 먼저 스스로 본다(그림은 열어 보고 · 화면은 찍어 본다). 화면 쪽은 스킬 `epos-self-check`.

## 2. 지피티 — 그림
- 부르는 법 · 모델표 · 점검표 · 기록 = 스킬 `epos-gpt-image`(`.claude/skills/`). 도구는 ChatGPT 앱 안에 이미 있다(깔지 않음).
- 모델 ⚑: 정해진 그림 = 가장 작은 모델(`gpt-6-luna` · 노력 낮음) · 새 지시문 = 기본 모델(`gpt-6.2-sol` · 낮음) · 가장 큰 모델(`gpt-6.2-astra`) = 쓰지 않음.
- 다시 만들기는 한 장에 한 번까지 — 두 번째도 어긋나면 멈추고 보고.
- ~~두 번째 눈 ⚑(팀장 해석 — 제제 확인 전): 그림이 기준에 맞나만 본다~~ → 🔵 **코드 검토는 클로드가 한다**(제제 2026-11-25 — 가장 큰 사용량 · 모델이 다채로움). 지피티에게 코드 검토를 맡기지 않는다.
- 그림 점검 ⚑: 제제의 뜻 = «나온 그림을 한 번 검토해야 헛된 다시 만들기가 줄고 의도한 결과가 나온다»(🔵 점검을 둔다). **누가 보나는 클로드 세션**(⚑ 팀장 처리 — 근거: 만든 쪽이 제 것을 보면 같은 것을 놓친다 · 지피티 사용량이 가장 귀하다 · 클로드는 그림을 볼 수 있고 사용량이 가장 크다). 스킬 `epos-gpt-image` 3절 그대로.
- 지피티 기본 설정을 낮춤(🔵 제제 11-25 «권장대로»): 옛 모델 · 가장 높은 노력 → `gpt-6.2-sol` · 중간. 옛 값은 `~/.codex/config.toml.bak-20261125`.

## 3. 제미나이 — 영상
- **명령줄 도구는 깔지 않는다**(팀장 확인 2026-11-25): 제미나이 명령줄 도구는 2026-06-18부터 구독 로그인(Pro · Ultra)을 받지 않고, Plus는 처음부터 받지 않았다 → 깔아도 구독으로 쓸 수 없다(돈을 따로 내는 열쇠가 필요). 이 컴퓨터에는 11-09에 한 번 로그인한 흔적만 있다.
- 뒤를 잇는 «안티그래비티 명령줄 도구»는 **보류** ⚑: Plus로 쓸 수 있다고 적혀 있으나 ① 유튜브 주소 분석이 문서에 없고, 영상은 사람이 붙여 넣는 방식만 적혀 있다 ② Plus에서 고를 수 있는 작은 모델이 2026-11-30에 빠진다고 적혀 있다 → 큰 모델 하나만 남을 수 있다(1절 3과 부딪침). 영상 일이 잦아지면 다시 본다.
- 길 🔵(제제 2026-11-25): **팀장이 앱 안 브라우저로 제미나이 앱을 직접 조작한다** — 제제가 옮겨 나르지 않는다(자동화의 뜻). 제제는 앱 안 브라우저에서 구글 로그인만 한 번(11-25 열어 보니 로그인 전). 요금제 = Plus. ~~제제가 붙여 넣고 답을 가져오는 길~~
- **시험 B 첫 판(11-25) = 실패**: 팀장이 앱 안 브라우저로 영상 세 편을 물음 → 제미나이(Hydrogen)가 «유튜브 링크에 접속하는 도구가 연결되어 있지 않다»며 세 편 모두 못 봄(지어내지는 않음). 짐작 ⚑: 제미나이 설정의 «연결된 앱 — 유튜브»가 꺼져 있음(계정 설정이라 제제가 켬). 켠 뒤 다시 잰다.
- **시험 B 둘째 판(11-25) = 성공**: 유튜브 연결은 이미 켜져 있었다(팀장의 짐작이 틀림 — 제제가 확인). 고친 것 둘 = 글머리에 `@YouTube`를 붙임 · 짧은 주소 대신 긴 주소(`youtube.com/watch?v=…`) · 한 편만. 1분 안에 시간 표시가 붙은 긴 요약이 나옴. **한계: 자막만 읽고 화면은 보지 않는다**(제미나이가 스스로 밝힘) · 영상 제목을 실제와 다르게 적음(내용은 재료로만 — 팀장이 거른다). 부르는 틀 ⚑: `@YouTube 이 영상 한 편을 요약해 줘: <긴 주소> — (묻는 것) · 화면을 봤는지 자막만 읽었는지 밝혀 줘 · 추측은 «추측»으로`.
- **시험 B 셋째 · 넷째 판(11-25) = 실패**: 짧은 영상 두 편을 묶어(요약 + 검색 조사) → 못 봄 · 한 편만 따로 → 못 봄(«도구 및 검색 호출 횟수 제한»이라고 답함). 네 번 가운데 한 번만 성공. 까닭은 가르지 못함 ⚑ — 후보: Plus의 도구 호출 한도가 그 사이 닳음 / 짧은 영상에는 자막이 없음. → **믿고 맡길 만큼 한결같지 않다.** 다음 판은 시간을 두고(한도가 풀린 뒤) 긴 영상 한 편으로 다시 잰다.
- 제제 제안(11-25): 영상에 나온 정보를 바탕으로 상세 조사까지 시키기 — 방향 좋음(영상 → 이름 → 조사). 다만 조사는 클로드가 맡는 쪽이 ⚑(제미나이의 검색 호출이 가장 먼저 닳았고, 클로드는 웹 검색 · 출처 읽기를 할 수 있고 사용량이 크다): **제미나이 = 영상에서 이름과 주장 뽑기 → 클로드 = 그 이름을 조사 · 검증**.
- 맡기는 일 🔵(제제 11-25): **영상 분석과 촬영 조사에만** — 사용량이 아주 빨리 닳는다. 아끼는 법 ⚑: 여러 편을 한 번에 묶어 묻기 · 빠른 쪽 모델 · 그림이 중요한 영상만(말이 전부인 영상은 글로 된 자료를 먼저 찾는다).
- 모델 ⚑: 짧은 영상 한 편 요약 = 앱의 빠른 쪽 · 여러 편 비교 · 판단이 필요한 것 = 깊은 쪽.
- 두 번째 눈 ⚑(제안): 우리 «통»의 플레이 녹화를 보여 «어디서 멈칫 · 어디가 심심»을 적게 한다 — 재미 검수의 보조(판정은 제제).
- 받은 요약은 «재료»다 — 팀장이 우리 규칙(금지선 · 🔵)으로 걸러 «가져올 것 / 버릴 것»으로 바꾼 뒤에만 쓴다.

## 4. 사용량의 원리 ⚑ (팀장이 재 보며 배운 것)
- 사용량 ≈ 모델 크기 × 노력 × 넣는 양 × 부르는 횟수.
- 일하는 도구(에이전트)는 부를 때마다 기본 짐이 붙는다 — 지피티에게 «OK»라고만 답하게 해도 13,506 토큰(11-25 실측 · 가장 작은 모델 · 낮은 노력). → 자잘하게 여러 번 말고 **묶어서 한 번**.
- 그림은 모델보다 **장 수 · 다시 만든 횟수**가 사용량을 정한다.
- 영상은 **길이**가 사용량을 정한다(1초에 수백 토큰쯤이라는 것이 일반 지식 — 앱에서 재 보지는 않음). → 필요한 구간만.
